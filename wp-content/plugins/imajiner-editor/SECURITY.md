# Storage security and integration

PHP theme editing is code execution. REST/admin callers must require `edit_themes`, cookie authentication plus a WordPress nonce for browser requests, and reject `DISALLOW_FILE_EDIT`. Storage is a lower-level API, not an authorization boundary: callers must enforce ownership and explicit acceptance of AI output. The store itself rejects writes when `DISALLOW_FILE_EDIT` is enabled.

## Wiring

- Include `includes/class-imajiner-filesystem.php` before any file-store operation; include `includes/class-imajiner-filesystem-credentials.php` after `Imajiner_Secrets`. Call `Imajiner_Filesystem_Credentials::init()` once. `Imajiner_Filesystem::init()` connects lazily and returns `true|WP_Error`; do not call it globally on every request.
- No JavaScript, enqueue or localization dependencies are introduced by this unit. Missing-access errors include HTTP 503 and `data.settings_url` pointing to Settings → Imajiner Filesystem. Error UIs should render that escaped link and let users retry, rather than dropping the error data.
- Common adapter methods: `read`, `write`, `mkdir`, `exists`, `delete`, `move`. Paths are absolute local WordPress paths, translated to the transport's `wp_content_dir()`. Only the active child theme and `uploads/imajiner/preview` are accepted; outside-content uploads and symlinked deployments fail closed. `delete` deletes a single file; no directory recursion. `list_files` is a flat cleanup helper. Additive helpers `exists_checked` (`bool|WP_Error`) and `permissions` (`int|WP_Error`) keep failed remote metadata checks from masquerading as missing files. The optional third argument to `write` supplies original permissions when rollback recreates a deleted file; two-argument callers are unchanged.
- Store additions: `delete($path,$hash)` and `rename($path,$new_path,$hash)`. Both snapshot revisions and roll back failed pairs. Rename keeps source bytes; the manager is responsible for post assignments and any explicitly accepted CSS/body-class changes. Destination PHP **or CSS** collisions are refused. Revisions follow the renamed template.
- The integrated design-system UI persists accepted tokens to child `assets/css/design-tokens.css` through `Imajiner_Design_System`, with explicit acceptance, hash checks and private revisions. Theme frontend/block-editor styles, AI prompts, editor suggestions and static proposal previews share this source. The store's separate `write_design_tokens()` helper targets `imajiner/design-tokens.css`; it is not the UI's persistence path.

## Guarantees and limits

Content operations go through WordPress filesystem transports. The direct transport subclasses `WP_Filesystem_Direct` only to replace its delete-first/copy-fallback move with same-directory native rename; it never degrades to copy. Temporary content is verified and receives existing permissions before replacement; PHP temporary/backup files end in `.php`, not publicly downloadable `.tmp`. Templates are syntax-checked before staging, and opcache/stat cache is invalidated after mutations. Web servers must execute/deny PHP in themes and deny hidden `.imj-*` staging files; never configure theme PHP as static downloads.

FTP/SSH cannot promise an atomic pair or a portable overwrite rename through WordPress. Existing remote targets move to random sibling backups, then verified temporary files move into place without overwrite; failures attempt restoration. Cross-file failures restore prior PHP/CSS or remove newly created files. Database revisions remain if restoration fails; `imajiner_rollback_failed` must not be shown as a successful save. Remote `move(...,true)` to an existing target is refused rather than using WordPress's destructive overwrite. Remote updates have a brief absent-target window and are **not atomic**. Backend failures/crashes may require administrator recovery; use maintenance windows for remote deployments.

Database locks serialize plugin operations for five minutes; stale hashes protect editor versions, not edits by external processes ignoring the lock. No transport can prevent an administrator or hostile process changing symlinks concurrently. Ancestor links are rejected locally; FTP listings reject both link types and `islink` flags. Core SSH listings follow links, so SFTP `lstat` checks each ancestor instead and fails closed if metadata is unavailable. FTP servers concealing remote symlinks cannot provide the same assurance and should not be used for editing.

Credentials use WordPress's native credential form, gated by `edit_themes`, the `filesystem-credentials` nonce and HTTPS. Only encrypted ten-minute per-user/session/theme credentials are saved; logout/theme changes and expiry invalidate them. Expiry is enforced on read even when cron is delayed, and `imajiner_fs_expire` removes expired ciphertext through WordPress cron. No decrypted keys or backend error objects enter REST responses/logs. WordPress may retain its normal hostname/username option, never the password. Prefer host-provisioned `FTP_*` constants for unattended writes. Salt/key rotation invalidates ciphertext. Sodium is mandatory for saving temporary credentials.

## Uninstall

Settings → Imajiner Filesystem offers an administrator-only nonce-protected checkbox, **off by default**, to remove preview cache and private template revisions. Child-theme PHP/CSS are never deleted. Uninstall always deletes plugin AI settings and encrypted filesystem credentials and unschedules credential expiry jobs. Opt-in cache cleanup is flat, nonrecursive and filename-allowlisted; links, unknown files and protective `index.php`/`.htaccess` files are retained so incomplete cleanup never removes access protections. Cleanup is bounded to 10,000 files and 10,000 revisions per site. If remote access is unavailable it leaves the cache rather than falling back to direct access. Multisite network-wide sweeps are deliberately not attempted.

## Integrated defensive boundaries

- REST save/stage/history/restore callbacks require `edit_themes`; WordPress maps this capability to false when `DISALLOW_FILE_EDIT` is enabled. Generation additionally requires `manage_options`. Cookie nonce enforcement is provided by WordPress REST authentication, not by `rest_do_request()` test dispatch.
- `Imajiner_Editor::get_template()` validates registry paths through the filesystem adapter before returning them. Preview source/cache paths are validated separately before execution.
- `Imajiner_Preview::build()` and `cache_dir()` use the adapter for content reads/writes, guarded PHP and cache protection files. Staging fails closed; temporary staged files are deleted at request shutdown. Preview jobs/proposals remain user/theme/hash bound.
- `Imajiner_Secrets` uses authenticated sodium secretbox and keeps API secrets out of frontend settings. It assumes sodium exists; settings should fail safely with a translated error if absent. Custom-provider URL changes must continue dropping saved keys. No provider calls were made in this unit.
